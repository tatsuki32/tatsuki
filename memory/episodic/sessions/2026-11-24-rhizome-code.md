## やったこと
- ログインの画面（`/_/login`）は前からあったが、どこからもリンクしていなかった。訪問者の画面の上に「Code」を置き、`/_/code` にした。「Sign in」と書くと訪問者が登録の要るサイトだと思うため。
- 1画面に「1. メール → Send code」「2. 6桁 → Open」を並べた。本人のアドレスのときだけメールが届き、返事はどのアドレスでも同じ。
- 入口が見えるようになるので守りを直した。前は回数の制限と誤入力の数が全員で共通で、他人の試し打ちで本人のコードが消え、入れなくなることがあった。
  - コードは頼んだブラウザだけで使える（cookie `rbq`、`codes.hash` は「ブラウザの印のハッシュ:コードのハッシュ」。表の形は変えていない）。
  - 回数の制限は訪問者ごと（IP の塩つきハッシュ、1日で消える）と宛先ごと。
  - メールは返事のあとに送る（かかる時間で本人のアドレスか分からない）。

## 追記：自動の安全確認の指摘を直した
- 誤入力の数は、番号を見る前に1文の UPDATE … RETURNING で使う（同時に送られても5回まで）。回数の制限も1文の INSERT … ON CONFLICT … RETURNING。
- 制限は訪問者ごとに1行（表 `limits`。前の `throttle` は使わない）。入力されたアドレスは残さない。古い行は時々まとめて消す。
- 本人宛てのメールは、知らないブラウザから1日30通・前に入ったブラウザから20通まで。上限でも返事は同じ。
- 公開の前に `npx wrangler d1 execute rhizomebox --remote --file schema.sql` が要る（表 `limits` を足す）。先に流してから deploy する。

## 追記：公開した
- 本人の OK で、表 `limits` を remote に足してから deploy。外から、入口・転送・非公開ページの 404・知らないアドレスへの返事を確かめた。本物のメールの受け取りは本人が試す。

# ノンデザイナーズ・デザインブック（第4版）から作る Desk の UI ルール

> 出典：Robin Williams『ノンデザイナーズ・デザインブック 第4版』日本語版（マイナビ出版, 2016）。
> 本文は要約・言い換え。引用は短い語句だけ。ページ番号は日本語版のもの。
> **注意**：Drive の文字変換は p.136（Chapter 8 のパンフレット）で止まる。
> Chapter 9〜15（欧文組版・活字・活字のコントラスト）と日本語版補足は本文がなく、目次の項目名だけ確認できた。
> 3章（タイポグラフィ）は、前半に出てくる活字の記述＋目次の項目名＋同書の一般に知られた内容で補った。補った箇所には【補】と付けた。

対象：Tatsuki's Desk（単一HTML・黒地＋金アクセント・日本語UI・iPhone 375px）。
ビュー：Home（今日の3つ・今日の習慣）/ Tasks / ノート / Calendar / World Desk / マイナー国 / Morning Mail / Inbox / 習慣 / Claude Log。

## 0. 本の前提（p.10〜14）

- 4原則は **近接・整列・反復・コントラスト**。どれか1つだけ使うことはまずない。
- 直す手順は「原則を知る → 使えていない所に気づく → 問題に名前を付ける → 直す」。
- 適用は1つずつ。順番は **近接 → 整列 → 反復 → コントラスト**（p.29, p.81）。
- 迷ったら「掃除」から：要らない要素・ラベル・枠をまず捨てる（p.92）。

## 1. 4原則

### 1-1. 近接（Proximity, p.15〜32）

**定義**：関係のあるものは近くに集め、1つの視覚的なまとまりにする。関係のないものは離す。近さそのものが「関係がある」という意味を持つ。
**目的**：組織化。まとまれば読まれやすく、覚えられやすい。副産物として空白も整理される。
**やり方（本）**：目を細めてページを見て、視線が止まる回数を数える。1画面で3〜5か所を超えたら、まとめられないか考える。
**避けること（本のまとめ）**：
- バラバラの要素を作りすぎる。
- 要素の間を **均等に** 空ける（見出しが上下どちらに属するか分からなくなる）。
- 見出し・キャプションがどの本文のものか迷わせる。
- 性質の違うものどうしを近づける。
- 空いているからという理由で、隅や中央に何かを置く。
- 改行2回打ちで空きを作る（段落の前後の空きを正確に指定する）。

**Desk のルール**
1. 余白は段階で決める：`--s1:4px / --s2:8px / --s3:16px / --s4:24px / --s5:40px`。
   **項目内 < 項目間 < セクション間** を必ず守る（例：行内 4、カード内の行間 8、カード間 16、セクション間 40）。
2. 見出しは「下の内容」に近づける。見出しの上の余白 ≥ 下の余白の2倍。
3. 1つのタスクの情報（名前・締切・状態）は1行かすぐ下にまとめる。締切を右端に遠く離さない。
4. Home の最初の画面で目が止まる所は3〜5個まで（例：日付・今日の3つ・今日の習慣・次の予定）。
5. 区切りはまず **空き** で作る。枠線や箱で囲むのは最後の手段（p.81「四角枠ではなく空き」）。
6. ラベルや補足（「メール：」「URL：」など見れば分かる語）は消す（p.92, p.119）。

### 1-2. 整列（Alignment, p.33〜54）

**定義**：ページ上のものを適当に置かない。どの要素も、ほかの何かと「見えない線」でつながるように置く。
**目的**：一体化と組織化。離れた要素も、線がそろっていれば同じものの一部に見える。
**やり方（本）**：物理的に離れていても、そろえられる相手を必ず探す。強い線を1本決めて、それを守る。
**避けること（本のまとめ）**：
- 1つの画面で複数の文字ぞろえ（中央＋左＋右）を混ぜる。
- 「とりあえず」の中央ぞろえ。中央ぞろえは縁が「ソフト」で弱く、退屈になりやすい。使うなら意図して、はっきり中央と分かる形で。
- 中央ぞろえの見出しの下に左ぞろえの本文を置く。
- 少しだけずれた配置（間違いに見える）。崩すなら大胆に崩す。
- 強い縁（画像・カード）の隣にでこぼこの縁を置いて、行き場のない空白を作る。

**Desk のルール**
1. 全ビューで **左ぞろえ1種類**。見出し・本文・ボタン・アイコンの左端を同じ線にそろえる。
2. 左の基準線は2本まで（外側の余白 16px と、カード内の余白）。それ以外の左位置を作らない。
3. 数字・日付・件数は **右端の線** にそろえる（本のメニュー例：値段を右でそろえる）。右ぞろえを使うのはこの列だけ。
4. 中央ぞろえは空の状態のメッセージなど、意図した1か所だけ。
5. 段落を字下げしない。区切りは段落間の空きで（字下げと空きを両方使わない, p.132）。
6. 画面幅 375px でも左右の余白 16px を固定し、要素がはみ出さない。はみ出すなら中途半端にしない。

### 1-3. 反復（Repetition, p.55〜68）

**定義**：色・形・線・書体・サイズ・配置など、目に見える特徴を全体で繰り返す。「一貫性」を一歩進めて、意識的なデザイン要素にしたもの。
**目的**：一体化と、見た目のおもしろさ。どのページも同じ出版物の一部だと分かる。
**やり方（本）**：すでにある一貫性（見出しの書体、罫線、ビュレット）を見つけて、それを強くする。慣れたら、反復のための要素を足す。全部同じでなくても、核になる要素が1〜2個あればまとまる。
**避けること（本のまとめ）**：
- うるさく、しつこく感じるほど繰り返す（例：全身赤だと焦点がぼける）。コントラストとの兼ね合いを考える。
- 記事ごとに書体や並べ方を変える。全部が違うと、どれも特別ではなくなる（p.130）。

**Desk のルール**
1. カードは1種類：同じ角丸・同じ内側余白・同じ背景色・同じ枠線（または枠なし）。全ビュー共通。
2. ビューの見出しは同じ書体・サイズ・太さ・上の余白・金色のアクセント（例：左の細い金線や先頭の記号）で統一。
3. 状態の表し方（期限切れ・進行中・完了）は全ビューで同じ形と色。Tasks と Home で違う表現にしない。
4. 金色は「反復の鍵」として、見出しの印・今の選択・主ボタンだけに使う。ほかの所に散らさない。
5. 一貫した土台があるから、1か所だけ違う扱い（例：今日の3つの1件目）が目立つ。特別扱いは1画面に1つ。

### 1-4. コントラスト（Contrast, p.69〜84）

**定義**：同じでない要素は、はっきり違うものにする。少しだけ違うのは「衝突」で、コントラストではない。
**目的**：目をページに引き込むことと、情報の階層を一目で分かるようにすること。焦点でないものを焦点に見せない。
**やり方（本）**：書体、線の太さ、色、形、サイズ、空き、テクスチャ、横と縦、行間などで差を付ける。本気で強調する。
**避けること（本のまとめ）**：
- 12pt と 14pt、0.5pt と 1pt の罫線、こげ茶と黒のような「ほとんど同じ」差。
- 似た書体を2つ使う。
- すべてを大きくする（全部大きいと、どれも目立たない, p.127）。
- 空白・非対称・極端に大きい/小さい文字を怖がる。

**Desk のルール**
1. 文字サイズは段を飛ばす：例 `12 / 14 / 20 / 28px`。13px と 14px のような近い値を並べない。
2. 太さも2段だけ：本文 400、見出し 700。500 と 600 を混ぜない。
3. 線は「なし」か「はっきりある」か。1px と 1.5px の線を同じ画面に混ぜない。
4. 各ビューに **焦点は1つ**（Home なら「今日の3つ」）。ほかは小さく・暗くして従わせる。
5. 補足情報（日付・出典・件数）は小さく、文字色も弱く。小さくすることを怖がらない（p.77）。
6. 目立たせるのは位置と太さが先。色は最後。習慣では赤・責める表示を出さない（Desk の決定）。

## 2. 色（Chapter 7, p.95〜112）

**本の要点**
- 12色のカラー・ホイール：原色 → 2次色 → 3次色。
- **補色**：真向かいの色。片方を主、片方をアクセントにすると最も効く。
- **トライアド**：等間隔の3色。**スプリット・コンプリメント**：補色の両隣を使う。少し洗練される。
- **類似色**：隣り合う色。共通の色を持つので調和し、落ち着く。
- **シェード**（黒を足す）と **チント**（白を足す）。1つの色相の濃淡だけで組む「単色的な組み合わせ」は、良い訓練になる。
- 補色や原色そのままは強すぎる。シェードやチントにすると大人っぽく豊かになる。
- **トーンに注意**：失敗するのはトーン（明るさ）が近すぎるときだけ。暗い背景に暗い赤の文字は沈む → 明るくする。トーンが近い色は隣り合わせず、量も同じにしない。
- **暖色は前に出て、寒色は引っ込む**。暖色は少量で効くので少なめに。色に同じ重みを持たせない。
- 迷ったら理屈から：決まった色があればそのシェードとチント、ロゴ色があればスプリット・コンプリメント。落ち着かせたいなら類似色、刺激なら補色。
- 繰り返し使う物は、先に自分のパレットを決めておく。
- 画面は RGB。

**黒地＋金の Desk ルール**
1. **パレットは先に固定**し、`:root` のトークン以外の色を使わない。
2. 地は「黒の単色的な組み合わせ」：背景・カード・浮いた面を、黒のチント3段で作る（例 `#0d0d0d / #171717 / #222`）。差ははっきり付ける。
3. 金は **暖色＝前に出る色**。面積は小さく（目安：画面の5%以下）。見出しの印・選択中・主ボタン・リンクだけ。
4. 金の濃淡（シェード／チント）で2〜3段を作る：強調用の明るい金、線や印用の落ち着いた金、背景用のごく暗い金。別の黄色を足さない。
5. 2色目が要るなら、金（黄〜橙）の **補色側＝青〜紫系** を、シェードにして寒色の脇役に使う（情報・リンク以外の区別など）。量は金より多くてよいが、明るさは抑える。
6. 文字色は白そのままにせず、明るいグレー（本文）と中間グレー（補足）の2段。トーンが近すぎて沈まないか、暗い面の上で必ず確かめる。
7. 赤は決まった意味にだけ使う：孤立リンク（Scrapbox 式）、要対応メール、締切切れ。習慣には使わない。面積は金より小さく。

## 3. タイポグラフィ（Chapter 9〜12 ほか）

**本の前半で確認できた要点**
- 似た書体を複数使わない（p.84）。差を付けるなら、はっきり違う書体・太さで。
- 細い本文と、太く黒い見出しの組み合わせは強い。標準の細めのサンセリフは、強い対比を作るには太さが足りない（p.132）。太さの幅があるファミリーを使う。
- 全部大文字は量が多いと読みにくい（p.27）。日本語では「全部太字」「全部大きい」に当たる。
- サンセリフで本文を組むなら、行間を少し広く、行の長さを短めに（p.132）。
- 行が長すぎると読者は引いてしまう。長い文は段を分けるか、要点を太字で抜き出して道しるべにする（p.76）。
- 段落の区切りは「空き」か「字下げ」のどちらか1つ。字下げするなら1字分（p.47, p.132）。

**目次で確認できた章立て（Chapter 10〜12）**：協調／衝突／コントラスト、活字のカテゴリー、活字のコントラスト（サイズ・太さ・構造・フォーム・方向・色）。
- 【補】**協調**：1つの書体ファミリーで、サイズや太さの差を小さく組む。静かでフォーマル。
- 【補】**衝突**：似ているが同じではない書体・サイズ・太さを並べる。落ち着かず、間違いに見える。避ける。
- 【補】**コントラスト**：はっきり違うものを組み合わせる。1種類の差だけでなく、複数の差（サイズ＋太さ＋色）を重ねると強い。
- 【補】6つの差の付け方：**サイズ**（大小）、**太さ**（細・太）、**構造**（書体の作り＝明朝とゴシックなど）、**フォーム**（字形＝大文字/小文字、正体/斜体）、**方向**（横組み/縦組み、行の長さ）、**色**（文字色・明るさ）。

**Desk のルール（見出し・本文・ラベル）**
1. 書体は1ファミリー（日本語ゴシック1つ）＋必要なら数字用1つまで。似たゴシックを2つ混ぜない。
2. 役割は3つだけ：**見出し**（20〜28px／700／明るい色）、**本文**（14〜16px／400／明るいグレー）、**ラベル・補足**（12px／400／中間グレー）。
3. 見出しと本文の差は、サイズだけでなく太さと色も変える（差を重ねる）。
4. ラベル類は小さく弱く。英字の全部大文字ラベルは使わない（表示は日本語）。
5. 本文の行間は 1.6〜1.8。長いテキスト（Morning Mail、World Desk の本文）は1行 35〜40字までに抑える（`max-width` を em か ch で）。
6. 数字（件数・日付・時刻）は等幅数字（`font-variant-numeric: tabular-nums`）で、右端の線にそろえる。
7. 長い記事は、要点の語を太字で抜き出す。ただし1段落に1つまで。全部太くしない。

## 4. その他の実用的なヒント

- **中央ぞろえを当たり前にしない**。意図したときだけ、はっきりと（p.36〜40）。
- **小さなずれ・小さな空きを作らない**。ずれは間違いに見える。そろえるか、大胆に崩すか（p.51, p.127）。
- **空白を怖がらない**。空白は目が休む場所。ただし要素の間で「行き場を失った空白」は要素を切り離す。空白も整理して流す（p.24, p.84, p.128）。
- **焦点は1つ**。一番おもしろいもの・一番大事なものを決めて大きく強くする。焦点で興味を持てば、小さい文字も読まれる（p.81, p.127）。
- **小見出しで拾い読みできるように**。多くの人は見出しだけを拾って全体をつかむ（p.127, p.131）。
- **箱の中に箱を入れない**。罫線で空間を閉じずに区切る、画像そのものを入れ物にする（p.130）。
- **グリッドを持つ**。土台のグリッドがあれば、要素がいくつかの段にまたがっても整って見える（p.130）。
- **土台がしっかりしていれば、遊べる**。特別扱いは強い一貫性の上でだけ効く（p.58, p.128）。
- **見る順番を設計する**。開いて最初に目に入るのが連絡先や著作権表示であってはいけない（p.133）。Desk なら開いて最初が設定や操作ボタンにならないように。
- **他人の良いレイアウトを参考にする**。気に入った例の構造を借り、中身は自分のものにする（p.94）。
- **ルールを破るには、まずルールを知る**（p.51）。

## 5. デザインレビュー用チェックリスト

画面を1枚ずつ、目を細めて見ながら確かめる。

1. [ ] 最初に目が行く所（焦点）は1つか。それが一番大事なものか。
2. [ ] 目が止まる所は3〜5個以内か。まとめられるものはないか。
3. [ ] 余白は「項目内 < 項目間 < セクション間」になっているか。均等な空きになっていないか。
4. [ ] 見出しは下の内容に近く、上とは離れているか。
5. [ ] 文字ぞろえは左ぞろえ1種類か（数字の右ぞろえ列を除く）。理由のない中央ぞろえはないか。
6. [ ] 左端の線は2本以内か。数ピクセルのずれはないか。
7. [ ] カード・見出し・状態表示は、全ビューで同じ形か。
8. [ ] 文字サイズ・太さ・線の太さに「少しだけ違う」組み合わせ（衝突）はないか。
9. [ ] 金色は見出しの印・選択中・主ボタン・リンクだけか。面積は小さいか。
10. [ ] 暗い面の上の文字は、トーンが近すぎて沈んでいないか。
11. [ ] 書体は1ファミリーか。似た書体を混ぜていないか。
12. [ ] 長い本文は1行40字前後までで、行間は十分か。
13. [ ] 箱の中に箱を入れていないか。枠の代わりに空きで区切れないか。
14. [ ] 見れば分かるラベル・飾り・説明を削ったか。
15. [ ] 375px 幅で横スクロールが出ず、左右の余白が保たれているか。

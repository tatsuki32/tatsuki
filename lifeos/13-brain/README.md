# 13 第二の脳

やりとりのあった相手の顧客メモを更新し、請求と入金を照合します。お金が動く操作は、本人の承認がないと実行されません。
会計と顧客管理のサービスは未決定なので、今あるのは「顧客メモの形」「照合」「承認の仕組み」です。外部にはまだつながっていません。

## 使い方

コマンドはすべて `python3 lifeos/13-brain/brain.py <命令>` です。

| 命令 | すること |
| --- | --- |
| `demo` | 見本のデータで全体を試す。本物のデータには触らない |
| `status` | 接続・対象の範囲・件数を見る |
| `contact add --name 名前 --addr 宛先 --alias 振込名義 --org 取引元` | 顧客メモを作る |
| `contact list` / `contact show 番号` / `contact edit 番号 --note メモ --next 次にすること` | メモを見る・直す |
| `ingest やりとり.json` | やりとりをメモに入れる |
| `sync` | つないだ先から取り込む（今は未接続と出る） |
| `unmatched` | 未登録の相手を見る |
| `reconcile --invoices 請求.csv --payments 入金.csv` | 照合する。`--propose` で一致分を承認待ちに入れる |
| `pending` | 承認待ちを見る |
| `approve 番号` / `reject 番号` | 承認する・却下する |
| `run 番号` | 承認済みを実行する |
| `retry 番号` | 失敗や結果不明のものを、承認からやり直す |
| `scope 会社名 …` | 対象の会社を決める（名前はデータ置き場にだけ残る） |
| `stop` / `start` | 止める・再開する |

### 顧客メモ

- 宛先は、メールアドレス、`@ドメイン`、電話番号で登録します。
- 自動で変わるのは「やりとり」と「最後のやりとり」だけです。「メモ」と「次にすること」は本人の言葉なので、上書きしません。
- 保存するのは件名と短い要約だけです。本文を渡しても捨てます。
- 未登録の相手はメモになりません。メルマガが顧客にならないようにするためです。`unmatched` で回数を確かめて、必要なら登録します。

`ingest` に渡す形は次のとおりです。同じものを2回入れても増えません。

```json
[{"channel": "gmail", "direction": "in", "address": "a@example.com", "at": "2026-11-01T09:00:00+07:00", "subject": "件名", "summary": "短い要約", "ref": "メッセージの番号"}]
```

### 照合

CSV の列名は日本語でも英語でも読みます。文字コードは UTF-8 と Shift_JIS です。

- 請求：`請求番号`・`取引先`・`金額`・`通貨`（必須）、`発行日`・`期日`・`状態`・`取引元`
- 入金：`振込人`・`入金額`・`通貨`（必須）、`番号`・`日付`・`摘要`

| 結果 | 意味 |
| --- | --- |
| 一致 | 請求番号と金額が同じ。または取引先と金額が同じで、ほかに候補がない |
| 差額あり | 請求は分かるが金額が違う |
| 要確認 | 金額だけ同じ、候補が複数、二重入金やまとめ払いの可能性 |
| 心当たりのない入金 | 当てはまる請求がない |
| 未入金 / 期限を過ぎた未入金 | 入金が見つからない請求 |

振込名義が会社名と違うときは、顧客メモの別名（`--alias`）に入れると取引先として認識します。

### お金の承認

1. `reconcile --propose` などが承認待ちを作ります。この時点では何も動きません。
2. 本人が普通のターミナルで `approve 番号` を打ち、内容を読んで金額を数字で打ちます。Claude の中や定期実行からは承認できません。
3. `run 番号` で1回だけ実行します。

- 承認のあとで金額・相手・中身が変わると実行しません。
- 期限は72時間です。
- 失敗したら自動でやり直しません。お金が動いた可能性があるので、確かめてから `retry` で承認を取り直します。
- 記録は `logs/brain-money.jsonl` に残ります。

この仕組みは、間違いや自動処理の暴走を止めるものです。データのファイルを意図して書き換える人までは止められません。送金権限を持つ認証情報は、つなぐときに必要最小限にしてください。

## つなぎ方（決まったら）

- 読むもの：`connectors.py` に関数を書き、下の `use()` で登録します。
- お金を動かすもの：`@approvals.money_action("accounting.write")` を付けて書きます。付けた関数は承認なしに呼ぶと拒否します。

```python
@approvals.money_action("accounting.apply_payment")
def apply_payment(action):
    ...  # action["amount"], action["target"], action["payload"]
```

Gmail はここからは送信しません。送信の機能を持っていません。

## 止め方

`brain.py stop` で、取り込み・照合・承認・実行と朝のブリーフィングへの出力が止まります。`brain.py start` で戻ります。
`tool.json` の `status` を `stopped` にしても同じです。常駐も定期実行もないので、ほかに止めるものはありません。

## データの置き場

`LIFEOS_DATA/tools/13-brain/`（`contacts.json`、`unmatched.json`、`approvals.json`、`reconcile.json`、`settings.json`）と `logs/brain-money.jsonl`。git には入りません。

# お宿 ひさ家 予約ページ（試作版）

営業日が月に4〜5日しかない宿のための、自社予約ページの試作です。

今の公式予約ページ（d-reserve）は、たまたま空いている日を選ばないとプランが出てきません。じゃらんは空いている日がわかるものの、画面がごちゃごちゃしています。
このページでは、**営業日と残りの部屋数を最初から並べて見せて**、日にち → プラン → お客様情報の3ステップで申し込めるようにしました。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | お客様が見る予約ページ |
| `admin.html` | 宿の人が空室を増やしたり減らしたりする画面（公開しない） |
| `data.js` | 営業日・残り部屋数・プランのデータ |

ブラウザで `index.html` を開けば、そのまま動きます。

## 宿の人の運用（メールで管理）

1. お客様が申し込むと、宿にメールが届く（フォームサービス経由。下の「公開までにやること」を参照）
2. 宿の人が電話かメールでお客様に確定の連絡をする
3. `admin.html` を開いてその日を押し、「−」で1室減らす
4. 「data.js を書き出す」で保存したファイルを、公開サイトの `data.js` と差し替える

じゃらん・楽天で予約が入ったときも、同じように3〜4で減らします。

## 公開までにやること

1. **プラン・料金・部屋数を宿に確認して** `data.js` を直す
2. **申し込みの送り先を決める**：Formspree などのフォームサービスに登録して、その URL を `data.js` の `formEndpoint` に入れる。入れると上の「試作版」の帯が消え、申し込みが宿のメールに届くようになる
3. **公開する**：GitHub Pages・Netlify・Cloudflare Pages など、HTTPS で無料公開できるところに `index.html` と `data.js` だけを置く（`admin.html` は置かない）
4. **プライバシーポリシーを作る**：集める情報、使い道、保存期間、問い合わせ先を書いて、予約ページからリンクする
5. **ダブルブッキング対策**：自社サイト・じゃらん・楽天の空室を同じ数で管理する。手作業で回せなくなったら「サイトコントローラー」で在庫を連動させる

## セキュリティ・個人情報で学ぶこと

予約ページは名前・電話・メールアドレスという個人情報を扱います。最低限、次の順で学ぶのがおすすめです。

1. **個人情報保護法の基本**：利用目的をはっきり示す、目的外に使わない、安全に保管する、漏れたときの報告義務。個人情報保護委員会の「中小企業向けガイドライン」がわかりやすい
2. **旅館業法の宿泊者名簿**：宿泊者の名簿は作って保管する義務がある。予約データとの関係を整理しておく
3. **HTTPS（通信の暗号化）**：入力した情報が途中で盗み見られないようにする。上の公開先なら自動で HTTPS になる
4. **自分で個人情報を持たない設計**：このページはサーバーにデータを保存せず、フォームサービス経由でメールに届けるだけにしている。保存する場所が少ないほど漏れにくい
5. **カード情報は扱わない**：カード決済をしたくなったら、Stripe などの決済サービスの画面に任せる（自分で受け取ると PCI DSS という厳しい基準が必要になる）
6. **アカウントの守り方**：フォームサービス・メール・GitHub に2段階認証をつける。予約メールを見られる人を限る
7. **スパム・いたずら対策**：フォームサービスの reCAPTCHA や Cloudflare Turnstile などを有効にする
8. **XSS（画面に悪いコードを埋め込まれる攻撃）**：お客様が入力した文字を画面に出すときは、HTML として解釈させない。このページでは `textContent` を使って対策している
9. **データの消し方**：宿泊が終わった予約メールをいつまで残すか決めて、不要になったら消す
